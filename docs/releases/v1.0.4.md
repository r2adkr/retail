> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**Games through the relay, faster Windows connects, and security fixes.** When two devices could not reach each other directly and a download shared the relay, a game's packets waited behind it: pings of seconds were possible. They now go first. On Windows, connecting and disconnecting no longer waits for PowerShell and netsh.

## What's changed

### The relay under load

- **Small packets go ahead of downloads.** Game, call and ping packets take their own lane on the device and on the server, so they no longer queue behind a download's large frames. Before, the last short packet of a download's burst could carry a ping along with it into the slow queue.
- **No seconds of queue.** A frame that waited more than 100 ms is dropped instead of sent late, and relay connections keep at most 32 KiB unsent in the system (16 KiB in TLS and the WebSocket).
- **BBR on Linux.** Relay sockets use BBR congestion control where the system has it.
- In tests on a 10 Mbit/s link, pings during a full download went from **about 470 ms to 65–80 ms** on average.
- Update the **server** as well as the devices: the lanes on the server's side come with the server.

> [!TIP]
> The relay is the fallback. For games, a direct connection is best: if your router allows it, forward UDP port 41641 to the device that plays (or to the exit node).

### Windows connects and disconnects faster

- The MagicDNS rule is written straight to the registry where Windows keeps it, instead of through PowerShell, which cost about a second on every connect and disconnect.
- Exit-node and subnet routes are added through Windows' IP Helper instead of one `netsh` process each (about 0.2 s apiece, 8 on connect with an exit node).
- The retail network adapter keeps one identity, so Windows recognises it as the same network each time.

### Security

Two rounds of review found no critical or high-severity issues. Fixed, among others:

- **Fair shares under one abuser.** One member can no longer fill another device's relay lane, the server's WebSocket tunnels, its registration and handshake limits, or REALITY's replay guard for everyone else. Idle tunnels close after 120 s; limits apply per IPv6 /64.
- **Netmap rounds paced.** A member could make the server send new netmaps to every device by repeatedly changing its device info; updates are now paced per device and ignored from expired devices.
- **Re-joining** sends the stored device token only to the server it was pinned to, not to a server key named by an invite.
- **Exit nodes and routers.** An exit node may send into the mesh only from internet addresses no other device routes. Linux and macOS routers forward into the mesh only replies. Forwarding without a system NAT gives each device its own share.
- **Local machine.** The admin token is written to a new file that no one else holds open; the Internet tunnel adopts only the cloudflared it started; on Windows, the proxy sign-in belongs to the console user who chose the proxy; `helper stop` removes the helper's identity.
- **Robustness.** An oversized chunk in an HTTP response can no longer stop the updater; server error text and invite addresses lose control characters before they reach a terminal; port mappings are undone when opening fails halfway.

### Other fixes

- Tray: the Internet tunnel hint in Korean and Japanese, and a failed setup step shown in red.

> [!NOTE]
> The relay changes were measured on Linux test networks. Windows does not offer per-socket BBR or the unsent-data limit, so a Windows **server** gains less; Windows and macOS devices gain fully from the server's side.

## Upgrading

Installed devices update themselves within a few hours (or at once: tray app → ⚙ → Settings → **Check now**). Running the new installer over an installed retail updates it as well. Server data, keys and settings stay.

Installing for the first time: see the [1.0.0 release notes](https://github.com/r2adkr/retail/releases/tag/v1.0.0) or the [README](https://github.com/r2adkr/retail#readme).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
