> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**The first release.** One installer per system sets up everything, and any device can host the network from its tray icon. No account, no cloud service, no separate server to install.

## Highlights

- **Direct connections through NATs**: STUN and hole punching over IPv4 and IPv6, with an automatic relay over HTTPS where no direct path exists.
- **Gets through restrictive networks**: blocked UDP, TLS-inspecting firewalls, company proxies (with Windows sign-in), CDNs, NAT64, and REALITY camouflage.
- **Any device is the server**: open a server from the tray app and invite others with a code, a QR code, or an installer that joins by itself. Works behind CGNAT with a helper node.
- **MagicDNS, access rules, subnet routes and exit nodes**: reach `nas.retail.internal` by name, limit who reaches what with tags and rules, reach a whole LAN through one device, or send internet traffic through another device.
- **Lost devices cut off with one click**; device keys can expire, and encrypted server backups restore or move the server with every device keeping its address and name.
- **Small and fast**: about 12 MB of memory, faster than wireguard-go in our [measurements](https://github.com/r2adkr/retail/blob/main/docs/DESIGN.md#12-performance), and builds for Raspberry Pi.
- **Desktop app** for Windows, macOS and Linux in English, Korean, Japanese, Chinese and Spanish, plus the `retail` CLI and a terminal UI (`retail tui`).

Each installer is one file that holds everything: the daemon `retaild` (runs as administrator/root, and is the server when the device hosts), the tray / menu bar app, and the `retail` CLI.

## Install

**Windows**: run `retail-windows-x86_64.exe`. It asks for administrator rights as it opens, installs, and offers to join a network with an invite code (or skip and join later from the tray icon). It ends by showing where retail's icon is.

**macOS**: open `retail-macos.dmg`, then open `retail.app` in it. The same setup asks for your password, installs, and offers to join a network.

**Ubuntu and Debian**: open the `.deb` (App Center installs it), then open **retail** from the app menu and paste an invite code. Members of the `sudo` group may control retail from the tray app. `sudo apt remove retail` removes it.

**Any Linux or macOS, from a terminal**:

```sh
curl -fsSL https://raw.githubusercontent.com/r2adkr/retail/main/scripts/install.sh | sh                       # install
curl -fsSL https://raw.githubusercontent.com/r2adkr/retail/main/scripts/install.sh | sh -s -- --invite <code>  # install and join a network
```

The script downloads the newest release, checks it against `SHA256SUMS`, installs through apt where there is apt, and registers the daemon with systemd (launchd on macOS).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Host a network

On any device, in the tray app: **⚙ → Manage server → Open server**, then **Create invite**. Or from a terminal:

```sh
retail server start
retail server invite
```

**A server without a screen** (Linux VPS, Raspberry Pi), in one command. It installs retail, starts it at boot, starts a server that does not join its own network and prints the first invite:

```sh
curl -fsSL https://raw.githubusercontent.com/r2adkr/retail/main/scripts/install.sh | sh -s -- --server
```

Or the server image:

```sh
docker run -d --name retail-server -p 443:443 -p 80:80 -p 3478:3478/udp -v retail-data:/data ghcr.io/r2adkr/retail:1.0.0
docker exec retail-server retail server invite
```

The server listens on TCP 443 (registration, control and relay), TCP 80 (for networks that allow only web traffic) and UDP 3478 (STUN). [Self-hosting](https://github.com/r2adkr/retail/blob/main/docs/SELF-HOSTING.md) covers domains, helper nodes, CDN and REALITY, access rules, subnet routes and backups.

## Join a network

Paste the invite code in the tray app (**⚙ → Settings → Connect**), or:

```sh
retail up --invite retail1.…
retail status        # devices, paths and names
```

A server can also hand out an installer that joins by itself: create an invite and save the installer for the other person's system from its **⋯** menu, in the server window or the web admin page.

## Updates

Installed devices update themselves from this page's releases (turn it off with `retail set --auto-update false`). Each update is checked against `SHA256SUMS` before it replaces the programs, and running a newer installer over an installed retail updates it as well.

## Security

- Devices talk over WireGuard (Noise IK); the control connection is TLS pinned to the server's own certificate, which the invite code carries.
- Changes through the daemon's local API need its token: on Windows any signed-in user, on Linux root or the `retail` group, on macOS administrators. Stopping the daemon and settings that hand out the Windows sign-in need administrator/root.
- Server backups are encrypted with a passphrase. Losing the server's certificate key without a backup means inviting every device again.
- Please report security problems privately rather than with details in a public issue: open an issue asking for a private contact.

## Known limitations

- retail takes addresses from `100.64.0.0/10`. Do not run it at the same time as another VPN that uses that range.
- Mesh addresses are IPv4 only; the paths between devices use IPv6 too.
- Where no direct connection is possible, traffic relays through the server, whose connection then limits the speed.
- MagicDNS needs systemd-resolved on Linux for the system to use it; elsewhere ask `100.100.100.100` directly.
- Integrated proxy sign-in works on Windows only; Linux and macOS use Basic and SOCKS5 passwords.
- Subnet routes on Windows and macOS have not been checked on real machines yet.
- No mobile apps yet.

The full list is in [Design → Known limitations](https://github.com/r2adkr/retail/blob/main/docs/DESIGN.md#14-known-limitations).

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
