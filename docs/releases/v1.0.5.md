> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**See why a device goes through the relay, and let retail open a router port for direct connections.** Settings has a new **Info** tab with traffic and each device's path. Any device can now ask its router to open its WireGuard port, and Windows relays keep their queue short.

## What's changed

### Info tab

Tray app → ⚙ → Settings → **Info** shows:

- **Usage**: data sent and received, retaild's peak memory, and how many devices are reached directly or through the relay. The counts start over when retail reconnects.
- **Each device's path and why**: same local network, directly across the internet, or through the relay because UDP is blocked on this network, the other device has no public address, a router or firewall blocked direct UDP, or the direct path went quiet.

`retail status` prints the same reason next to each device's path.

### Open a router port (opt-in)

- Settings → **This device** → **Open a router port** asks the router (PCP, NAT-PMP or UPnP) to open this device's WireGuard UDP port. Devices on other networks then connect to it directly instead of through the relay.
- Off by default. The setting shows the result: opened with which method, or refused, with the port to forward by hand.
- `retail set --open-router-port` does the same from the command line.
- A device that hosts the network already opens its ports; the server's notice about ports to forward now names the WireGuard UDP port as well.

### Windows relay connections

- Relay sockets on Windows keep only what the link needs plus 32 KiB unsent, following the system's ideal send backlog, so a download no longer builds seconds of queue in front of a game's packets on Windows servers and devices.

> [!NOTE]
> The Windows relay change is measured only on test networks so far; real links may differ.

## Upgrading

Installed devices update themselves within a few hours (or at once: tray app → ⚙ → Settings → **Check now**). Running the new installer over an installed retail updates it as well. Server data, keys and settings stay.

Installing for the first time: see the [1.0.0 release notes](https://github.com/r2adkr/retail/releases/tag/v1.0.0) or the [README](https://github.com/r2adkr/retail#readme).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
