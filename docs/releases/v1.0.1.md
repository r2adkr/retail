> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**A bug-fix release for 1.0.0.** Servers can now be reached on networks whose provider blocks incoming web ports, and the tray app picks up a reinstall right away. Installed devices update themselves; nothing needs to change on your side.

## What's changed

### Servers on more networks

- **A second server port.** Besides TCP 443 and 80, a server now also listens on a TCP port picked at random once per server (between 20000 and 31999, kept across restarts). Some internet providers block 80 and 443 coming in, and some routers keep 443 for their own remote management while still answering that they forwarded it. The router opens the new port with the others (PCP, NAT-PMP or UPnP).
- **Invites name every way in.** Invite codes list the server's public address on both ports, and devices try them at the same time, as they already did for every address in a code. Devices on 1.0.0 use the new addresses too.
- **Ports forwarded by hand work without a domain.** When the router opens nothing automatically (UPnP off), retail still asks it for its public address and puts that address into invites. Forward the ports the server window lists to the server's computer, and devices on other networks can join.
- The server window, the web admin page and the "forward these ports" notice show the second port, for example *Opened with NAT-PMP (TCP 443, 24581, UDP 3478)*.

> [!IMPORTANT]
> If you host a network, **make a new invite after updating**: codes made before 1.0.1 do not name the second port. Devices that already joined learn it from the server by themselves.

### Fixes

- The tray app restarts into the new program whenever an update or a reinstall replaces it, also when the version stays the same. Before, reinstalling the same version left the old tray app (and its old windows) running until the next sign-in.

### Docker

The server image picks its second port the same way. Publish it as well (it is in `host.json` in the data volume after the first start), or leave it out: devices then use 443 and 80 as before.

## Upgrading

Installed devices update themselves within a few hours (or at once: tray app → ⚙ → Settings → **Check now**). Running the new installer over an installed retail updates it as well. Server data, keys and settings stay.

Installing for the first time: see the [1.0.0 release notes](https://github.com/r2adkr/retail/releases/tag/v1.0.0) or the [README](https://github.com/r2adkr/retail#readme).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
