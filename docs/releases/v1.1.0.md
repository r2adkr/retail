> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**Send files between devices, wake devices that are off, and relay through your own devices.** Also an upload limit that keeps games and calls quick while a download fills the line, and a round-trip graph in the Info tab.

## What's changed

### Sending files

- A device's ⋯ menu has **Send a file…**. The file goes straight to that device through the tunnel.
- The other device asks with a notification: a toast with **Accept** and **Decline** on Windows, a dialog on macOS, a notification with buttons on Linux (or a small window where the notification cannot show buttons).
- Accepted files land in Downloads under a free name: `name (2).ext` rather than over an existing file. Declining, or no answer within 2 minutes, tells the sender.

### Wake-on-LAN

- A device that is off shows **Wake up** in its ⋯ menu (CLI: `retail wake NAME`). This device, or any online device on the same home network, sends the wake-up. The device's network card must have Wake-on-LAN turned on in its BIOS or settings.

### Relay for others

- Settings → **Relay for others** (CLI: `retail set --relay-for-others`), off by default. Two devices that cannot connect directly then go over UDP through such a device instead of the server's relay, which is usually faster. The tray shows **Via NAME**.
- The device passes on only traffic between devices it reaches directly itself, at most 200 Mbit/s for each of them, and within its upload limit. It cannot read that traffic: WireGuard stays end to end.

### Upload limit

- Settings → **Upload limit** (CLI: `retail set --upload-limit MBIT` or `off`), off by default. When a download through an exit node fills the exit's upload, everything else waits behind it in the router. Set a little under the line's upload speed, retail slows the big transfers and lets small packets (games, calls, DNS) through on time.

### Round trips

- The Info tab shows a device's round trip and a graph of the last 5 minutes, measured while traffic flows. Idle devices are not pinged.

### Fixes

- When only one direction of a direct path breaks, the relay takes over within about 3 seconds again.
- A part of retaild that stops along with its session is no longer reported as a failure and restarted twice.

## Upgrading

Installed devices update themselves within a few hours (or at once: tray app → ⚙ → Settings → **Check now**). Running the new installer over an installed retail updates it as well. Server data, keys and settings stay.

Sending files, waking devices and relaying through a device need both devices on 1.1.0, and Wake-on-LAN and relaying also need the server on 1.1.0. Older devices keep working with newer ones.

Installing for the first time: see the [1.0.0 release notes](https://github.com/r2adkr/retail/releases/tag/v1.0.0) or the [README](https://github.com/r2adkr/retail#readme).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
