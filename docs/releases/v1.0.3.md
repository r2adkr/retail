> retail is a self-hosted mesh VPN. Your devices reach each other directly over WireGuard, from any network, through a server you run yourself: on one of your own devices or on a small VPS.

**A bug-fix release for 1.0.2.** On Windows 10 and 11 Home, turning on **Offer as exit node** failed with a PowerShell error (`New-NetNat`, HRESULT 0x80041010). Home editions do not include the NAT that retail used for this. Now a Home PC can be an exit node, and route networks for the mesh, without it.

## What's changed

### Exit nodes and routed networks on Windows Home

- **Forwarding through retail itself.** Where Windows has no built-in NAT (WinNAT comes with Hyper-V, which Home editions lack), retail forwards for the mesh on its own:
  - It opens the connection to the destination first, then hands the device's connection to Windows' own TCP stack and joins the two.
  - A destination that cannot be reached is refused at once, as it would be without retail in between.
  - UDP (DNS, games, calls) and ping work too.
- **IP forwarding stays off, and no NAT is set up.** While a Home PC is an exit node, retail adds a Windows Firewall rule that lets its own program receive these connections, and removes the rule when you turn the exit node off. If you use another firewall, it may need to allow `retaild.exe`.
- **Speed and memory.** In tests it carries several gigabits per second, a little less than the system NAT. An idle connection costs retail about 9 KB, because buffers are used only while data moves.
- **Safety.** Whatever a route says, retail never forwards to addresses that only the PC itself or its local link answers: loopback, link-local (`169.254.x.x`, cloud metadata included), multicast and retail's own range. As before, an exit node keeps its own private networks (`10.x`, `172.16–31.x`, `192.168.x`) to itself unless it routes them.
- Windows Pro, Enterprise and Server keep using the built-in NAT, as in 1.0.2.

### Other fixes

- **Readable errors from Windows tools.** When a Windows tool fails while retail sets up forwarding, the message is read in the console's code page (Korean, Japanese and Chinese Windows included) and cut to its first line, instead of the whole PowerShell script.
- **macOS refuses before saving.** Turning on **Offer as exit node** on a Mac (which cannot be one) now says so right away and leaves the switch off. A setting saved by an earlier version is dropped when retail starts.
- Turning the exit node off on Windows also turns forwarding off on retail's interface again.

> [!NOTE]
> The forwarding without a built-in NAT was tested on Linux, where it can be turned on for tests, not yet on a real Windows Home PC. If something does not work, `C:\ProgramData\retail\retaild.log` shows "forwarding for the mesh through this device's own network stack" when it starts; please include the log in an issue.

## Upgrading

Installed devices update themselves within a few hours (or at once: tray app → ⚙ → Settings → **Check now**). Running the new installer over an installed retail updates it as well. Server data, keys and settings stay.

Installing for the first time: see the [1.0.0 release notes](https://github.com/r2adkr/retail/releases/tag/v1.0.0) or the [README](https://github.com/r2adkr/retail#readme).

> [!NOTE]
> The installers are not code-signed yet. Windows SmartScreen asks to confirm: **More info → Run anyway**. macOS Gatekeeper wants **right-click → Open** the first time.

## Verify your download

`SHA256SUMS` lists every installer's checksum (also below).

```sh
grep retail-linux-x86_64.deb SHA256SUMS | sha256sum -c     # Linux: prints OK
grep retail-macos.dmg SHA256SUMS | shasum -a 256 -c          # macOS: prints OK
```

```powershell
(Get-FileHash .\retail-windows-x86_64.exe).Hash           # Windows: compare with SHA256SUMS
```
